# 工作表重建後的核取方塊定位失效

日期：2026-10-29

## 已確認原因

Excel COM 連線能找到目前開啟的寄單工作簿與「進階篩選」工作表。欄位仍為 B 欄姓名、C 欄電話；核取方塊位於 M 欄。

本次掃描停止的原因是工作表被重建或替換：範例工作簿的內部 sheetId 從 39 改為 40，而舊 `_SMS_M_` 隱藏名稱仍指向已不存在的工作表，因此變成 `#REF!`。工作表顯示名稱相同，不代表仍是原本的工作表物件。

## 本次修復與驗證

先完整備份目前工作簿，再以先前成功修復的稽核記錄比對全部 149 個控制項：名稱、列號、欄位、LinkedCell、OnAction、Caption 均須一致；可見方塊須完整落在原記錄的儲存格範圍。只有全部符合才將既有失效名稱重新指到目前工作表的對應 M 欄儲存格。

重新連結後，以原有 `get_checked_patients()` 執行唯讀掃描，確認 18 個勾選控制項對應 18 筆病患、18 個手機目標。勾選與儲存格內容／公式保持不變，未實際寄送簡訊。

## 發布範圍與限制

這次重新連結是在特定工作簿中完成的修復，沒有變更 Python 正式程式，也不會隨安裝包套用到其他工作簿。1.0.1 安裝包包含之前已合併的核取方塊修復功能；它不會自動恢復失效錨點，遇到壞掉的錨點仍會停止。

日後若再次刪除、複製替換或重建「進階篩選」工作表，必須重新驗證定位。不要在一般掃描時忽略 `#REF!` 並直接以畫面位置推測病患。若要產品化重建定位流程，需提供完整預檢、可信的方塊對應依據、備份與還原、明確的重新配對介面，再另外建置新版本。

本說明不包含工作簿、病患姓名／電話、寄送歷史、授權資料或登入憑證。
